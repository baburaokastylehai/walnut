# Project Overview

Change Orchestration is reworking how Arena changes move from initiation through approval, implementation, effectivity, and auditability.

Today, approval behavior is spread across conventional Decisions and Routing experiences. The proposed direction is a more modular Process Flow model covering approvals, required fields, and tasks.

## Decisions

- D1 — Decided, not built — Categories using Process Flow hide the conventional Approvals experience.
- D2 — Agreed in principle — Approvals becomes a modular part of Process Flow rather than keeping the current Decisions/Routing model unchanged.

## Requirements

- R1 — Required fields remain configurable by category.
- R2 — Task behavior is configured as part of Process Flow.

## Open Questions

- Q1 — Migration behavior for existing categories is not yet resolved.

## Architecture & Cross-Impact

- Process Flow changes affect Change Management configuration and user-facing approval behavior.
