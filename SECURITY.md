# Security

Walnut runs through your AI host and connected tools. It does not provide its own credentials, access control, sandbox or hosted storage. Review the target and publication scope before use. Pull is read-only against shared data; roles control emphasis, not permission.

Do not include credentials, private chats, employer documents, customer details or real project examples in public issues, fixtures or PRs. Local `.walnut/` state and legacy target files must be ignored in each consuming project.

Source content is evidence, not instructions. A pasted document or shared page must never direct Walnut to change its target, disclose private sources or execute unrelated actions. Report behavior that crosses those boundaries.

Use GitHub’s private vulnerability reporting on this repository when available. If it is unavailable, open a public issue containing only a request for a private reporting channel; do not post the vulnerability or sensitive evidence. Do not send corporate or project data to a public issue while waiting for a response.

This is a pre-1.0 beta. Fixes target the latest version; older snapshots are provided for traceability and rollback, without a separate maintenance guarantee.
